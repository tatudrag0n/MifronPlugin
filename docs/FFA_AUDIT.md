# FFAバランス・安全性監査

更新日: 2026-08-29（JST）

## 監査範囲

`FfaKit`、`FfaConfig`、`FfaManager`、FFA報酬処理、フィールドアイテム処理を静的に確認した。コードだけでは実際の勝率・平均戦闘時間・マップ依存性を証明できないため、実戦データを伴わない項目は「未判定」として扱う。

## 確認結果

- 現在のキットは18種類で、キットごとに防具、主武器、能力、クールダウン、弱点の説明が分かれている。
- FFA報酬は同一対象への短時間の連続報酬を抑制する既存処理を利用する。
- 投射物・召喚物・罠には所有者情報が付与され、離脱・終了時の後片付け経路がある。
- ネクロマンサーの召喚物は時間経過で削除されるが、従来は所有者単位・FFA全体の同時存在数をコード上で制限していなかった。

## 実施した安全修正

ネクロマンサーに以下の設定可能な上限を追加した。

```yaml
ffa:
  kits:
    necromancer:
      max-owned-mobs: 3
      max-global-mobs: 20
```

召喚前に無効・死亡済みの記録を掃除し、所有者上限または全体上限へ達している場合はスポーンしない。これにより、召喚物量産による負荷上昇・視界妨害・人数差の過度な固定化を抑える。既存のプレイヤーセッション終了時の削除処理は維持している。

## 未判定・要観測

- キット別の勝率、キル率、死亡率、平均戦闘時間
- Java / Bedrock別の命中率・操作差
- マップごとの遠距離キット有利不利
- スポーンキル、無限コンボ、実戦上のクールダウン回避
- ネクロマンサー以外の能力の体感バランス

運営判断として大幅な数値変更を行う前に、キット・マップ・プラットフォーム・セッションを含む匿名集計を蓄積し、提案と人間レビューを通す。現時点で「全キットが均衡している」とは判定しない。

## 検証

`mvn -B test` を実行し、既存テストを含む12テストが成功した。上限判定の境界値は `FfaSummonRulesTest` で、所有者上限・全体上限・不正な設定値の最小値補正を確認している。
