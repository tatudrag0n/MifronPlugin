# FFA以外の現行コード仕様

この文書は `main` のJava実装と同梱YAMLを基準にしています。企画上の予定ではなく、現在動く処理だけを記載します。

## 初期配布と移動

- 初回を含む参加時にウォレット、ステータスを確認・更新します。
- 参加時に配布されるのは「メニュー」1個だけです。旧配布アイテム(emerald_bundle、friend_book、quest_book、teleporter、online_shop、hub_compass)とTebexストア案内アイテムは参加時に回収します。
- メニューの「ウォレット」クリックで残高表示ができます。「メニュー」は旧ウォレットアイテム(emerald_bundle)と同等の棚ショップの決済アイテムです。Bundleとしての収納は無効です。
- 通常のコンパスクリックはキャンセルされ、意図しないテレポートを防ぎます。

## MP

- 通常のエメラルド取得ではMPは増えません。
- MPは討伐、進捗、クエスト、ジョブ、ログイン・滞在報酬、取引などで増減します。
- FFA外で死亡すると、その時点の所持MPの50%を失います。端数は切り捨てです。
- `/mf pay <player> <amount>` は既知のプレイヤーへMPを送ります。自分宛てと残高不足は拒否します。
- 残高は0～2,000,000,000に制限されます。

## 棚ショップ

- 棚の3枠に表示されるアイテムは商品見本で、スタック数は在庫数ではありません。
- 同じ素材の在庫は全棚で共有されます。初期在庫は0で、プレイヤーの売却により増え、購入により減ります。
- 「メニュー」(または旧ウォレットのemerald_bundle)を持って商品枠を右クリックすると、在庫とMPを消費して購入します。「メニュー」を右手にした棚ショップの右クリックは、ファンメニューを開かずに購入へ進みます。
- 表示商品と同じ通常アイテムを持って右クリックすると1個売却します。Mifron専用アイテムとショップワンドは売却できません。
- 通常棚は商品カタログの番号順に3商品を表示します。Shift+右クリックでは、オフハンドの商品を選択枠へ個別指定できます。
- ショップ化ブロックは通常破壊、爆発、ピストン、液体、延焼から保護されます。

## 樽ショップと商人

- 樽ショップは「空の樽+棚」で構成します。OnlineShopの特別品から入手できる専用棚を樽の上に置いて作成します(販売棚=オーク材、買取棚=スプラウス材)。
- 販売棚は樽内の在庫を1個ずつ、棚に設定された価格(既定1,000MP)で販売し、買取棚は客が持つアイテムを1個樽へ移して同価格でMPを支払います。価格は棚ごとにPDCへ保存され、現状の変更UIはありません。
- 棚と樽は作成者しか開けられず、客はクリック取引だけができます。
- Mifron商人はSurvivalの中央広場外にだけ生成でき、購入用・売却用の候補を各8件保存します。UIには1ページ6件を表示します。
- 商人はクリックで1個、Shift+クリックで可能な限り一括取引します。

## クエスト

- デイリーとウィークリーは候補から期間ごとに5件を決定し、マンスリーは全件表示します。
- 完全達成クエストは、その期間に表示された通常クエストの達成数から進捗を算出します。
- 自動加算される主な値は採掘、設置、敵対Mob討伐、初訪問チャンク、釣り・自然採集、繁殖、進捗、ボス参加、取引、転生、ジョブ行動（job_hunt/job_harvest/job_enchant/job_trade/job_fish/job_mine/job_explore）です。
- 旧来の運営付与条件も、ゾンビ村人治療、古代都市・ピグリン要塞関連進捗、専用ワールド到達、建築提出・承認、レア釣果、農作物売却、鍛冶型拾得から自動判定します。
- 敵対Mobとボスの参加判定は、討伐前30秒以内に最大体力の20%以上を与えるか、とどめを刺すことです。
- バベル、ギンヌンガガプ、アガルタ、エリシオン、国家の判定ワールド名は `quests.automatic.world-progress` で変更できます。
- 報酬表示と支払通貨はMPです。転生補正は `quests.reward.*` に従います。

## ジョブ

- 7職＋無職の単一選択。`/mf job` で確認、`/mf job <名>` の2段階確定で変更。切替クールダウンは `jobs.change-cooldown-hours`（既定24h）。
- 所得ボーナスは `jobs.bonus.<行動>`（既定：討伐20%、売却10%）、職限定の微少報酬は `jobs.base.<行動>`。
- 固有特典：鍛冶屋は上限突破（`jobs.enchanter-limit-break` 既定+5）と超過倍率軽減（`jobs.enchanter-multiplier-scale` 既定0.5）、商人は購入割引上乗せ（`jobs.merchant-purchase-discount-percent` 既定10）、釣り人は宝釣り（`jobs.fisher-treasure-emerald/diamond`）。
- ジョブクエストJ01-J07は `job` 指定職のみ表示・進行するデイリー。
- ジョブレベルは対応行動のXP(`jobs.leveling.xp.*`)から算出し、必要量は `jobs.leveling`(base-xp既定100、成長+15%/Lv、最大50)で決まります。保存先は `players.<uuid>.job.xp` です。
- レベルごとに収入ボーナスが `bonus-percent-per-level`(既定+0.5%、上限 `bonus-max-percent` 既定25%)加算されます。`jobs.leveling.titles` の節目で称号(常連/熟練者/達人)を解放し、`broadcast-levels` で全体告知します。
- ジョブUIのレベル表示(スロット4)とメニューのジョブ項目名に現在レベルを表示します。

## 安全取引

- `/trade <player>|accept|deny|cancel|money <額>`。共有54枠UIで提示し、双方確定で成立。
- 上限は `trade.max-amount`（既定100万MP）。MP移動は `EconomyManager.transfer`（デッドロック回避ロック）経由。

## Buildワールドと建築提出

- `/mf build enter` でUUIDごとのフラットワールドを必要時に作成し、Creativeへ変更します。
- モブ、時間経過、PvPは無効、KeepInventoryは有効です。既定のワールド境界は直径256ブロック、初期足場は中心から半径16ブロックです。
- WorldEdit権限はBuildワールド滞在中だけ付与されます。空間制限はWorldEdit側ではなくワールド境界です。
- 一般プレイヤーは他人のBuildワールドへ入れません。管理者は訪問と編集ができます。
- `/mf structure submit <name>` は現在のWorldEditクリップボードをSchematicとして提出します。管理者の承認後だけSurvivalへ設置できます。
- 設置済み範囲では破壊・設置、爆発、ピストン、液体、額縁・防具立て・コンテナ操作を禁止します。

## ワールド・保護・再生成

- 全ワールドでKeepInventoryを有効にします。PvPは既定で無効です。
- SurvivalではTNTと溶岩の設置・使用・ディスペンサー発射を禁止します。
- 中央保護はHubのチャンクを中心にした正方形範囲です。設定半径は最小4チャンクです。
- 中央・追加保護チャンクではコンテナ、扉、赤石操作、額縁、防具立て、看板、ホッパー移送、爆発、ピストン、液体、延焼を制限します。
- 中央・追加保護チャンクに対する通常のブロック破壊・設置を止めるリスナーは現行コードにありません。
- `/mf regen [radius]`(管理者) は Survival・ロード済み・保護外・除外外のチャンクを実APIで再生成します。月次の自動再生成(`regen.monthly-enabled` / `interval-days` / `monthly-max-chunks`)も動きます。除外は `regen.excluded-chunks` だけで、旧キー `regen.allowed-chunks` は設定から削除済みです。

## インベントリ分離

- 保存グループはSurvival系と通常系の2種類です。NetherとEndは名前に関係なくSurvival系です。
- Survival系と通常系は所持品、装備、オフハンド、選択スロット、レベル、経験値、満腹度、隠し満腹度を別々の `.dat` に保存します。
- グループ読込時のHPは最大HPと20の小さい方へ戻します。Potion EffectとEnder Chestはグループ保存対象ではありません。

## ProposalとMinoru

- Proposalコマンドは管理者専用で、`proposals.yml` のpendingを一覧・確認・承認・強制承認・却下・再読込します。
- 提案の作成はゲーム内にありません。閲覧と賛成投票は `/mf vote`(メニューの「提案」)で行え、pending提案を1ページ45件で表示してクリックで賛成票の付与・取消ができます。
- 承認で設定へ反映できる種類は `title` と `custom_item` だけです。`shop_item` は廃止済みです。
- Minoru連携コードは6桁、10分有効、1回使用で失効します。APIが無効な場合は発行できません。
- Minoru APIはBearer認証を使い、プレイヤー照会、MP照会、重複防止付きMP増減・設定を提供します。

## チャット方針

- ゲーム内は全体チャットのみを提供します。個人宛DM(旧フレンドチャット)は廃止しました。
- `/tell` `/msg` `/w` `/whisper` `/message` `/m` `/t` `/r` `/reply` `/mail` `/em` `/email` と `/team msg` は `ChatPolicyFeature` が遮断します。追加ラベルは `chat.blocked-private-commands` で指定します。
- 遮断は電気通信事業法の整理(「場」の提供は届出不要、宛先指定の媒介は届出対象)を前提にしています。個人宛機能を再追加する場合は事前に総合通信局へ確認し、必要なら届出を行ってください。
- 削除済みのフレンドチャット送信経路は復活させないでください。

## ログイン・復帰・投票

- ログイン報酬は連続日数に応じて増額し、連続7/30/100日などの節目で追加報酬と全体告知があります。節目は `login-bonus.streak-milestones` で変更できます。
- メニューの「ログボ」で連続日数・累計・次の節目を確認できます。
- 14日以上空けて復帰すると `return-bonus.days` / `return-bonus.mp` に従い復帰ボーナスを受け取ります。
- メニューの「投票」は VotingPlugin の `/vote` を開きます。投票報酬は VotingPlugin 側で設定します。

## 初日導線と紹介

- 初参加時に歓迎タイトルと全体告知を出し、チュートリアル卒業時は全体告知と「目標」チェックリストを自動表示します。
- 目標は menu / job / 採掘64 / 売却 / チャンク保護 / クエスト受取の6項目。各 `starter-goals.reward-mp`(既定300MP)をUIから1回だけ受け取れます。
- `/mf refer` で6桁コードを発行(`referral.code-ttl-hours` 既定48h)。参加 `referral.eligible-days`(既定7日)以内の新規が `/mf refer <code>` で登録し、卒業時に双方が `referral.reward-mp-invitee/inviter`(既定3000MP)を獲得します。
- 紹介は1人1回まで、紹介者の報酬は週 `referral.weekly-cap`(既定5件)まで。紹介者がオフラインの場合は次回ログイン時に通知します。

## 定期イベント

- `events.<id>` に週次の曜日・時刻・長さ・事前告知分数を設定します(既定: `fishing-festival` 土曜20:00・60分・15分前告知・有効)。
- 30秒間隔のタスクが事前告知・開始・終了を全体へブロードキャストします。
- `quests.yml` の `event: <id>` を付けたクエストは該当イベントの開催中のみ表示されます(例: S30「釣り大会 完走」)。
- `/mf event list|start <id> [分]|stop` は管理者向けの手動制御です。手動開催状態は `events.manual-active/until` に保存されます。

## 自動停止

- 最後のプレイヤー退出後、既定600秒でホスト停止を予約します。再参加すると予約を取り消します。
- 停止直前にプレイヤー、ワールド、Mifronデータを保存します。実行方法はGCE停止または任意コマンドです。
