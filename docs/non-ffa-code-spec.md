# FFA以外の現行コード仕様

この文書は `main` のJava実装と同梱YAMLを基準にしています。企画上の予定ではなく、現在動く処理だけを記載します。

## 初期配布と移動

- 参加時に配布されるのは「メニュー」(ネザースター)1個だけです。旧配布アイテム(emerald_bundle、friend_book、quest_book、teleporter、online_shop、hub_compass)とTebexストア案内アイテムは参加時に回収します。
- メニューの「ウォレット」クリックで残高表示ができます。「メニュー」は旧ウォレットアイテム(emerald_bundle)と同等の棚ショップの決済アイテムです。Bundleとしての収納は無効です。
- 初参加は自動でチュートリアルへ移動する。卒業/スキップ時に遊び方本「Mifron はじめの一歩」を配布し、`/mf guide` とメニューの「ガイド」から再取得できる。旧版の本は次回ログイン時に自動更新される。
- 通常のコンパスクリックはキャンセルされ、意図しないテレポートを防ぎます。

## チュートリアルとガイド

- 初参加者は自動で `tutorial` ワールドへ移動し、7段階（メニュー → ゾンビ3体 → Elite → レリック使用 → クエスト/目標 → 金床 → 卒業）を進む。進捗は `data.yml` の `tutorial.stage` に保存され、途中離脱後も再開できる。
- `/mf tutorial [restart|skip]`（`/tutorial` も可）で再開・やり直し・スキップ。スキップは残り報酬なしでSurvivalへ出る。
- 卒業/スキップ時に遊び方本「Mifron はじめの一歩」を配布。`/mf guide` とメニューの「ガイド」から再取得でき、旧版(v1)は次回ログイン時に最新版(v2)へ自動更新される。
- 案内板は `TutorialSigns` が起動時にコードから再生成する。Buildワールドは既定無効のため、建築提案はガイドに載せない。
- チュートリアル内の配布装備は通常系インベントリに入り、Survival系とは分離される。

## MP

- 通常のエメラルド取得ではMPは増えません。
- MPは討伐、進捗、クエスト、ログイン・滞在報酬、取引などで増減します。
- FFA外で死亡すると、その時点の所持MPの50%を失います。端数は切り捨てです。
- `/mf pay <player> <amount>` は既知のプレイヤーへMPを送ります。自分宛てと残高不足は拒否します。
- 残高は0～2,000,000,000に制限されます。

## 棚ショップ

- 棚の3枠に表示されるアイテムは商品見本で、スタック数は在庫数ではありません。
- 同じ素材の在庫は全棚で共有されます。初期在庫は0で、プレイヤーの売却により増え、購入により減ります。
- 「メニュー」(または旧ウォレットのemerald_bundle)を持って商品枠を右クリックすると、在庫とMPを消費して購入します。「メニュー」を右手にした棚ショップの右クリックは、ファンメニューを開かずに購入へ進みます。
- 表示商品と同じ通常アイテムを持って右クリックすると1個売却します。Mifron専用アイテムとショップワンドは売却できません。
- 通常棚は商品カタログの番号順に3商品を表示します。Shift+右クリックでは、オフハンドの商品を選択枠へ個別指定できます。
- ショップ化ブロックは通常破壊、爆発、ピストン、液体、延焼から保護されます。

## 樽ショップと商人

- 樽ショップは「空の樽+棚」で構成します。OnlineShopの特別品から入手できる専用棚を樽の上に置いて作成します(販売棚=オーク材、買取棚=スプラウス材)。
- 販売棚は樽内の在庫を1個ずつ、棚に設定された価格(既定1,000MP)で販売し、買取棚は客が持つアイテムを1個樽へ移して同価格でMPを支払います。価格は棚ごとにPDCへ保存され、現状の変更UIはありません。
- 棚と樽は作成者しか開けられず、客はクリック取引だけができます。
- Mifron商人はSurvivalの中央広場外にだけ生成でき、購入用・売却用の候補を各8件保存します。UIには1ページ6件を表示します。
- 商人はクリックで1個、Shift+クリックで可能な限り一括取引します。

## クエスト

- デイリーとウィークリーは候補から期間ごとに5件を決定し、マンスリーは全件表示します。
- 完全達成クエストは、その期間に表示された通常クエストの達成数から進捗を算出します。
- 自動加算される主な値は採掘、設置、敵対Mob討伐、初訪問チャンク、釣り・自然採集、繁殖、進捗、ボス参加、取引、転生です。
- 旧来の運営付与条件も、ゾンビ村人治療、古代都市・ピグリン要塞関連進捗、専用ワールド到達、建築提出・承認、レア釣果、農作物売却、鍛冶型拾得から自動判定します。
- 敵対Mobとボスの参加判定は、討伐前30秒以内に最大体力の20%以上を与えるか、とどめを刺すことです。
- バベル、ギンヌンガガプ、アガルタ、エリシオン、国家の判定ワールド名は `quests.automatic.world-progress` で変更できます。
- 報酬表示と支払通貨はMPです。転生補正は `quests.reward.*` に従います。

## レリック

- 判定はPDC `relic_id`。素材の入手（EntityPickupItemEvent）とクラフト（CraftItemEvent）時に素材ごとの低確率で1個だけ変化する。`/give` とクリエイティブのインベントリ取得でも同じ確率判定を行う。
- 変化確率は `素材の希少性(baseChance) × レリックの強さ(multiplier)`。基本確率は COMMON 0.100% / UNCOMMON 0.200% / RARE 0.400% / EPIC 0.800% / LEGENDARY 1.600%、倍率は MINOR ×1.0 / MEDIUM ×0.5 / MAJOR ×0.2。残響の結晶が0.200%になるよう調整している。
- Elite討伐時はバニーホップが2%でドロップする。エリートWardenをプレイヤーが討伐した場合は、通常のエリートドロップとは別に残響の結晶を確定で1個ドロップする。
- `/mf relic <id> [player]` で付与。旧ID（scratch/recall/phoenix/tide/swift/guardian/wind等）はエイリアスとして受理し、使用時に表示・IDを新しい形へ自動更新する。
- 右クリック系はクールダウン制で、残り時間はバニラのアイテムクールダウン表示（`setCooldown`）で示す。チャットには残り秒数を出さない。所持パッシブ（磁力の石・死不知のトーテム・空に海写す蒼球・反射の守護盾など）は専用の周期タスクで処理する。
- フックショットのウキは重力を切り、視線方向へ毎tick速度を再設定して直線に飛ばす。地面・壁面・天井を問わず、ウキの周囲に非通過ブロックがあればその手前で停止する。停止後は右クリックでウキの位置へプレイヤーを引き寄せる。
- バニーホップは使用後に一度空中へ出て着地するまで再使用できない。クールダウン表示は着地まで続く。
- 空に海写す蒼球の移動速度低下・泳ぎポーズ・浮遊効果は、実際の空中泳ぎ中だけ適用する。ジェットパック噴射中やバニーホップの滞空中はすべて無効化し、着地・水中・ログイン・リスポーン時にも速度補正とポーズをリセットする。
- 錬金の砥石は設置型。プレイヤーが設置した砥石の位置を記憶し、`PrepareGrindstoneEvent` で剥がしたエンチャントを本にして返す。破壊時はレリック本体をドロップする。
- サプライズ・チェーン（ID: `chain`）は左クリックで最大30ブロック先のMOBを拘束し、再左クリックで解放、スニーク+左クリックで全解除する。右クリックは新規拘束のみで、既存の鎖を解除しない。拘束中は `setAI(false)` で停止し、バニラのリードは使わず毎tickの速度補間で滑らかに追従させる。距離による自動解除はない。
- 竜の吐息は指向性ビーム（毎tick前進）で、当たったMOBにダメージ+炎上+鈍足、壁または最大射程で終点爆発する。
- 空に海写す蒼球は空中で浮遊・上昇・緩降下し、泳ぎ姿勢はクライアント専用パケット（NMS、リフレクション）で付与する。空中移動は `GENERIC_MOVEMENT_SPEED` の乗算モディファイア（×0.4）で水中スプリント泳ぎ相当（約2.2m/s）に落とす。実際の水/溶岩中ではバニラの泳ぎを妨げない。

## 安全取引

- `/trade <player>|accept|deny|cancel|money <額>`。共有54枠UIで提示し、双方確定で成立。
- 上限は `trade.max-amount`（既定100万MP）。MP移動は `EconomyManager.transfer`（デッドロック回避ロック）経由。

## Buildワールドと建築提出（既定無効）

- `build-world.enabled` と `main-world.enabled` は既定で `false`。無効時は `/mf build enter|exit` は動作せず、プレイヤー別Buildワールドも作成しない。遊び方ガイド・案内板でも案内しない。
- 有効化した場合のみ `/mf build enter` でUUIDごとのフラットワールドを必要時に作成し、Creativeへ変更する。
- 有効時の仕様: モブ、時間経過、PvPは無効、KeepInventoryは有効。既定のワールド境界は直径256ブロック、初期足場は中心から半径16ブロック。
- WorldEdit権限はBuildワールド滞在中だけ付与され、空間制限はWorldEdit側ではなくワールド境界で行う。一般プレイヤーは他人のBuildワールドへ入れず、管理者は訪問・編集できる。
- `/mf structure submit <name>` はBuildワールド内でのみ、現在のWorldEditクリップボードをSchematicとして提出する。管理者の承認後だけSurvivalへ設置する。
- 設置済み範囲では破壊・設置、爆発、ピストン、液体、額縁・防具立て・コンテナ操作を禁止する。

## ワールド・保護・再生成

- 全ワールドでKeepInventoryを有効にします。PvPは既定で無効です。
- SurvivalではTNTと溶岩の設置・使用・ディスペンサー発射を禁止します。
- 中央保護はHubのチャンクを中心にした正方形範囲です。設定半径は最小4チャンクです。
- 中央・追加保護チャンクではコンテナ、扉、赤石操作、額縁、防具立て、看板、ホッパー移送、爆発、ピストン、液体、延焼を制限します。
- 中央・追加保護チャンクに対する通常のブロック破壊・設置を止めるリスナーは現行コードにありません。
- `/mf regen [radius]`(管理者) は Survival・ロード済み・保護外・除外外のチャンクを実APIで再生成します。月次の自動再生成(`regen.monthly-enabled` / `interval-days` / `monthly-max-chunks`)も動きます。コードが参照する除外キーは `regen.excluded-chunks` で、旧 `regen.allowed-chunks` は残っていても無視されます。

## インベントリ分離

- 保存グループはSurvival系と通常系の2種類です。NetherとEndは名前に関係なくSurvival系です。
- Survival系と通常系は所持品、装備、オフハンド、選択スロット、レベル、経験値、満腹度、隠し満腹度を別々の `.dat` に保存します。
- グループ読込時のHPは最大HPと20の小さい方へ戻します。Potion EffectとEnder Chestはグループ保存対象ではありません。

## ProposalとMinoru

- クエスト提案は `/mf quest propose` でゲーム内作成できる。種類→名前→条件→必要数→報酬→依存→称号の順に入力し、pendingとして `proposals.yml` に保存する。`/mf quest cancel` で中断できる。
- 提案の閲覧・賛成投票は `/mf vote`。pending提案を1ページ45件で表示し、クリックで賛成票の付与・取消ができる。メニューの「投票」は VotingPlugin の外部投票サイトで、提案投票とは別。
- 管理者は `/mf proposal list|review|approve|forceapprove|reject|reload` で審査する。承認で設定へ反映できる種類は `title` と `custom_item` など設定で扱う種類に限る。`shop_item` は廃止済み。
- 建築提出はBuildワールド有効時のみ `/mf structure submit` で行い、管理者承認後にSurvivalへ設置する（既定は無効）。
- Minoru連携コードは6桁、10分有効、1回使用で失効します。APIが無効な場合は発行できません。
- Minoru APIはBearer認証を使い、プレイヤー照会、MP照会、重複防止付きMP増減・設定を提供します。

## チャット方針

- ゲーム内は全体チャットのみを提供します。個人宛DM(旧フレンドチャット)は廃止しました。
- `/tell` `/msg` `/w` `/whisper` `/message` `/m` `/t` `/r` `/reply` `/mail` `/em` `/email` と `/team msg` は `ChatPolicyFeature` が遮断します。追加ラベルは `chat.blocked-private-commands` で指定します。
- 遮断は電気通信事業法の整理(「場」の提供は届出不要、宛先指定の媒介は届出対象)を前提にしています。個人宛機能を再追加する場合は事前に総合通信局へ確認し、必要なら届出を行ってください。
- 削除済みのフレンドチャット送信経路は復活させないでください。

## ログイン・復帰・投票

- ログイン報酬は連続日数に応じて増額し、連続7/30/100日などの節目で追加報酬と全体告知があります。節目は `login-bonus.streak-milestones` で変更できます。
- メニューの「ログボ」で連続日数・累計・次の節目を確認できます。
- 14日以上空けて復帰すると `return-bonus.days` / `return-bonus.mp` に従い復帰ボーナスを受け取ります。
- メニューの「投票」は VotingPlugin の `/vote` を開きます。投票報酬は VotingPlugin 側で設定します。

## 初日導線と紹介

- 初参加時に歓迎タイトルと全体告知を出し、チュートリアル卒業時は全体告知と「目標」チェックリストを自動表示します。
- 目標は menu / 採掘64 / 売却 / チャンク保護 / クエスト受取の5項目。各 `starter-goals.reward-mp`(既定300MP)をUIから1回だけ受け取れます。
- `/mf refer` で6桁コードを発行(`referral.code-ttl-hours` 既定48h)。参加 `referral.eligible-days`(既定7日)以内の新規が `/mf refer <code>` で登録し、卒業時に双方が `referral.reward-mp-invitee/inviter`(既定3000MP)を獲得します。
- 紹介は1人1回まで、紹介者の報酬は週 `referral.weekly-cap`(既定5件)まで。紹介者がオフラインの場合は次回ログイン時に通知します。

## 定期イベント

- `events.<id>` に週次の曜日・時刻・長さ・事前告知分数を設定します(既定: `fishing-festival` 土曜20:00・60分・15分前告知・有効)。
- 30秒間隔のタスクが事前告知・開始・終了を全体へブロードキャストします。
- `quests.yml` の `event: <id>` を付けたクエストは該当イベントの開催中のみ表示されます(例: S30「釣り大会 完走」)。
- `/mf event list|start <id> [分]|stop` は管理者向けの手動制御です。手動開催状態は `events.manual-active/until` に保存されます。

## 自動停止

- 最後のプレイヤー退出後、既定600秒でホスト停止を予約します。再参加すると予約を取り消します。
- 停止直前にプレイヤー、ワールド、Mifronデータを保存します。実行方法はGCE停止または任意コマンドです。
