# FFA以外の現行コード仕様

この文書は `main` のJava実装と同梱YAMLを基準にしています。企画上の予定ではなく、現在動く処理だけを記載します。

## 初期配布と移動

- 初回を含む参加時にウォレット、ステータスを確認・更新します。
- ウォレットは左クリックで残高表示、棚・オークションでは右クリックで使用します。Bundleとしての収納は無効です。
- ステータスアイテムは右クリックでステータスUIを開きます。
- 通常のコンパスクリックはキャンセルされ、意図しないテレポートを防ぎます。

## MP

- 通常のエメラルド取得ではMPは増えません。
- MPは討伐、進捗、クエスト、ジョブ、ログイン・滞在報酬、取引などで増減します。
- FFA外で死亡すると、その時点の所持MPの50%を失います。端数は切り捨てです。
- `/mf pay <player> <amount>` は既知のプレイヤーへMPを送ります。自分宛てと残高不足は拒否します。
- 残高は0～2,000,000,000に制限されます。

## 棚ショップ

- 棚の3枠に表示されるアイテムは商品見本で、スタック数は在庫数ではありません。
- 同じ素材の在庫は全棚で共有されます。初期在庫は0で、プレイヤーの売却により増え、購入により減ります。
- ウォレットを持って商品枠を右クリックすると、在庫とMPを消費して購入します。
- 表示商品と同じ通常アイテムを持って右クリックすると1個売却します。Mifron専用アイテムとショップワンドは売却できません。
- 通常棚は商品カタログの番号順に3商品を表示します。Shift+右クリックでは、オフハンドの商品を選択枠へ個別指定できます。
- ショップ化ブロックは通常破壊、爆発、ピストン、液体、延焼から保護されます。

## 樽ショップと商人

- 樽ショップは既定で27商品を生成し、先頭3枠を掘り出し物枠として抽選します。
- 購入は常に1個です。購入した枠だけ、その場で別商品へ再抽選されます。
- Mifron商人はSurvivalの中央広場外にだけ生成でき、購入用・売却用の候補を各8件保存します。UIには1ページ6件を表示します。
- 商人はクリックで1個、Shift+クリックで可能な限り一括取引します。

## オークション

- 旧ショップワンドで、価格表上オークション可能なアイテム入り額縁をオークション化します。現行の額縁ショップワンドは未実装です。
- ウォレットで右クリックすると現在の最高額へ100MP、Shift中は1,000MPを加えた額で入札します。値は `auction.bid-step` と `auction.sneak-bid-step` で変更できます。
- 入札MPは即時に一時預かりされます。他人が最高額を更新すると、それまでの最高入札者へ全額返金します。出品者は自分の商品へ入札できません。
- `auction.duration-minutes` 経過後、最高入札者へ商品、出品者へ落札額を自動配送します。落札者がオフラインなら次回ログイン時に商品を渡します。
- 入札なしの場合は商品を額縁に残します。出品者または管理者が期間中に解除した場合も商品を残し、預かりMPを返金します。
- 旧版で記録だけされていた未徴収入札は、無料返金や未払い落札を防ぐため初回読込時に無効化します。

## クエスト

- デイリーとウィークリーは候補から期間ごとに5件を決定し、マンスリーは全件表示します。
- 完全達成クエストは、その期間に表示された通常クエストの達成数から進捗を算出します。
- 自動加算される主な値は採掘、設置、敵対Mob討伐、初訪問チャンク、釣り・自然採集、繁殖、進捗、ボス参加、取引、転生、ジョブ行動（job_hunt/job_harvest/job_enchant/job_trade/job_fish/job_mine/job_explore）です。
- 旧来の運営付与条件も、ゾンビ村人治療、古代都市・ピグリン要塞関連進捗、専用ワールド到達、建築提出・承認、レア釣果、農作物売却、鍛冶型拾得から自動判定します。
- 敵対Mobとボスの参加判定は、討伐前30秒以内に最大体力の20%以上を与えるか、とどめを刺すことです。
- バベル、ギンヌンガガプ、アガルタ、エリシオン、国家の判定ワールド名は `quests.automatic.world-progress` で変更できます。
- 報酬表示と支払通貨はMPです。転生補正は `quests.reward.*` に従います。

## ジョブ

- 7職＋無職の単一選択。`/mf job` で確認、`/mf job <名>` の2段階確定で変更。切替クールダウンは `jobs.change-cooldown-hours`（既定24h）。
- 所得ボーナスは `jobs.bonus.<行動>`（既定：討伐20%、売却10%）、職限定の微少報酬は `jobs.base.<行動>`。
- 固有特典：付呪師は上限突破（`jobs.enchanter-limit-break` 既定+5）と超過倍率軽減（`jobs.enchanter-multiplier-scale` 既定0.5）、商人は購入割引上乗せ（`jobs.merchant-purchase-discount-percent` 既定10）、釣り人は宝釣り（`jobs.fisher-treasure-emerald/diamond`）。
- ジョブクエストJ01-J07は `job` 指定職のみ表示・進行するデイリー。

## 安全取引

- `/trade <player>|accept|deny|cancel|money <額>`。共有54枠UIで提示し、双方確定で成立。
- 上限は `trade.max-amount`（既定100万MP）。MP移動は `EconomyManager.transfer`（デッドロック回避ロック）経由。

## Buildワールドと建築提出

- `/mf build enter` でUUIDごとのフラットワールドを必要時に作成し、Creativeへ変更します。
- モブ、時間経過、PvPは無効、KeepInventoryは有効です。既定のワールド境界は直径256ブロック、初期足場は中心から半径16ブロックです。
- WorldEdit権限はBuildワールド滞在中だけ付与されます。空間制限はWorldEdit側ではなくワールド境界です。
- 一般プレイヤーは他人のBuildワールドへ入れません。管理者は訪問と編集ができます。
- `/mf structure submit <name>` は現在のWorldEditクリップボードをSchematicとして提出します。管理者の承認後だけSurvivalへ設置できます。
- 設置済み範囲では破壊・設置、爆発、ピストン、液体、額縁・防具立て・コンテナ操作を禁止します。

## ワールド・保護・再生成

- 全ワールドでKeepInventoryを有効にします。PvPは既定で無効です。
- SurvivalではTNTと溶岩の設置・使用・ディスペンサー発射を禁止します。
- 中央保護はHubのチャンクを中心にした正方形範囲です。設定半径は最小4チャンクです。
- 中央・追加保護チャンクではコンテナ、扉、赤石操作、額縁、防具立て、看板、ホッパー移送、爆発、ピストン、液体、延焼を制限します。
- 中央・追加保護チャンクに対する通常のブロック破壊・設置を止めるリスナーは現行コードにありません。
- `regen.allowed-chunks` は候補管理と設置警告に使いますが、現行Paper APIでは実再生成が無効で `/mf regen` は失敗します。

## インベントリ分離

- 保存グループはSurvival系と通常系の2種類です。NetherとEndは名前に関係なくSurvival系です。
- Survival系と通常系は所持品、装備、オフハンド、選択スロット、レベル、経験値、満腹度、隠し満腹度を別々の `.dat` に保存します。
- グループ読込時のHPは最大HPと20の小さい方へ戻します。Potion EffectとEnder Chestはグループ保存対象ではありません。

## ProposalとMinoru

- Proposalコマンドは管理者専用で、`proposals.yml` のpendingを一覧・確認・承認・強制承認・却下・再読込します。
- ゲーム内での提案作成・投票はありません。承認で設定へ反映できる種類は `title` と `custom_item` だけです。`shop_item` は廃止済みです。
- Minoru連携コードは6桁、10分有効、1回使用で失効します。APIが無効な場合は発行できません。
- Minoru APIはBearer認証を使い、プレイヤー照会、MP照会、重複防止付きMP増減・設定を提供します。

## 自動停止

- 最後のプレイヤー退出後、既定600秒でホスト停止を予約します。再参加すると予約を取り消します。
- 停止直前にプレイヤー、ワールド、Mifronデータを保存します。実行方法はGCE停止または任意コマンドです。
